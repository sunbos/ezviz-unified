# 组件路径与目录：本地验收

基线：`085bee1a81f7a90d5c852c3832c919a180498ddb`。代码、测试、修订和测试执行由 Claude Code 经 Magpie 使用 `devin/swe-2`、effort=max 完成；Codex确定方案、核对来源和实际工具输出、审查差异与验收边界。

## 范围与来源

- 增加完整路径段参数、显式 `JSON_NULL`、国内组件目录和独立报文评测支持；不把路径式接口与头部式 OTAP 自动合并。
- 12 页重新获取的正文哈希与原归档一致，身份与哈希见[来源记录](../../validation/2026-11-15-component-sources.json)。这不能证明官网资料完整或所有语义已确认。
- 目录共 9 条元数据，其中 7 条可调用；847 缺选盘依据、3873 模板含义未确认，仅保留不可调用记录。
- 登记变为 203 项契约/绑定，国内 137、海外 66，涉及 153 篇契约来源文档及 86 项来源问题。计数不代表全部 API 覆盖率。
- 新增组件未调用真实设备；型号、白名单、成功示例与物理效果的证据边界保留在契约和目录中。

## 被拒绝的候选及修正

- 修正文档链接的臆造路径、无正文 GET 漏传必填 Content-Type，以及仅因 PUT 就把官方查询语义判为写操作的问题。
- 修复模板反向花括号绕过，以及新增 property 导致原 Operation 校验变为不可达代码的问题；保留原地区、token、策略及只读标志校验。
- 拒收把异常链检查改为“隐藏上下文”的测试修订。恢复严格断言后先观察到同步/异步两项失败，再修复实现，使异常真正不保留敏感上下文；140 项相关测试通过。
- 评测严格区分空请求体与 JSON null，同时接受合法 JSON 空白；不能为匹配实现而发明字节级空白禁令。
- 修正契约中的布尔 `required_uncertainty`、非法空 `data_path` 和未经证实的温度缩放推断。
- 测试夹具使用未提供标记区分省略参数和显式 None，并直接断言反例确实发送预期的 null 数据，避免测试名称与实际覆盖不符。

两个较大任务曾在控制器时限结束时留下部分文件，未作为完整交付接受；后续限定范围重新审查并补完。辅助命令越界尝试和被拒绝的调用单独记录，不能将这些执行描述为全程无偏离。最后修复任务使用精确授权命令，未发生文件越界。
