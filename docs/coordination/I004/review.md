# HTTP 候选清单验收

## 分工与修订

Claude Code 经 Magpie 使用 `devin/swe-2`、`max` 生成解析器、归档适配器、独立测试及文档候选。代码与测试分开派单，文档与 CI 更新并行交付；Codex 核对来源、审查候选并执行本地检查。纯文本任务未执行自测，结果以本地验证为准。

审查拒绝了按位置配对地址与方法、从登记表补全声明、错误归档结构，以及不完整或不符合交付协议的输出。修订保留来源中的歧义。末轮回归分别复现并修复了元信息小节后的普通段落被误当作操作标题，以及查询参数丢失于精确关联判断的问题；同路由提示仍保留。独立复核另发现行内标签被吞作上一标签取值的问题，已以三种排版回归复现并修复。关于缺少 `platform` 应拒绝的建议未采纳：采集器明确允许缺失或 null，仅非空值必须匹配区域；补充注释并保留原校验。

## 验证结果

- 新工具专项测试：163 项通过。
- 全库离线测试：3188 项及 11 项 subtests 通过。
- 契约审计与摘要一致；186 条已审契约的 1520 次离线传输评测通过。
- Ruff 检查与 139 个纳入文件的格式检查通过；SDK 的 38 个文件通过 mypy。
- wheel、sdist 构建与元数据检查通过；干净安装、mock smoke 和 sdist 内 2132 项 SDK 测试通过。未发布 PyPI。
- 11 份真实归档样本得到预期 21 条声明，其中 20 条精确关联既有契约，1 条为待审线索。全主库扫描前后输入哈希一致；格式整理、查询参数及行内标签边界修复后，扫描内容均未变。

## 证据与限制

[机器摘要](../../validation/2026-11-15-endpoint-inventory.json)记录输入与实现哈希。全主库 2269 条记录中有 2221 份正文、48 条不可用；提取到的 1529 条声明中，1483 条具备明确方法及地址，46 条仍不明确。这些是出现次数，不是去重 API 数或支持率。

186 条已审契约中，184 条恢复到精确来源声明；`global.playback.invalidate`（海外 534）与 `global.security.update_password`（海外 2868）的声明地址含残留反引号，保留为未恢复，不自动修补。全文清单保存在被忽略的 `data/reports/`，不提交原始 HTML 或示例凭据。

本次没有调用真实设备 API。零候选文档可能含未支持的排版格式，静态 SDK 参考库与附件不在本次扫描范围内。新增接口仍需逐条审核契约与权限，不能直接从候选清单生成支持声明。
