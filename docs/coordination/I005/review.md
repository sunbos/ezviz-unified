# 文档解析修复验收

基线为 `dc592362fef439aed74831cf00bc8958b44ae385`。本批只修正已有文档工具及来源记录，不新增 SDK 业务接口、遥测后端或通用 shell 解释器。

## 变更

- 已审核契约的路径模板可以按原文字面关联来源：仍要求地区、文档 ID、URL、正文哈希、方法和路径同时相等，不展开参数，也不从登记补齐声明。
- curl 示例按引号和转义边界处理多行内容，避免将 JSON 内换行拆成新命令或把引用内分隔符当成 shell 控制符。复杂、不支持的结构保留为未知，不执行任何示例。
- 补充进程超时保护的终止性回归，覆盖 `$`、重定向字符、未引用模板等真实验收暴露的问题。
- 刷新主门户快照并修正研究报告和路线图的口径。原文与静态 SDK 参考库分开；不将图表首行变体数当成请求 schema 数，也不将 doc_id 写成数量。

## 验收证据

- Claude Code 经 Magpie 使用 `devin/swe-2`、effort=max 生成代码与执行常规检查；Codex对照原文、检查差异，并独立执行真实语料验收。
- 完整 pytest：3,808 passed，11 subtests passed；CI 范围 Ruff 检查通过。
- 相关 parser/inventory 回归：253 passed；其中多行与终止性用例 57 passed。
- 新快照：2,269 条记录、2,221 条正文、48 条源缺项；独立完整性与结构校验错误数为 0。静态参考页和附件本批未刷新。
- 真实全库扫描在约 41.6 秒内完成；203 项登记契约中恢复 201 项，另两项既有原文标记问题保留为未恢复，不伪造匹配。
- 选定组件语料仍为 996 条记录、882 个示例；旧解析器的 141 个 `unparsed_curl` 观察降为 0，仍有 21 个 invalid-address 观察待分类。这些计数不代表 API 总数、接口支持率或官网损坏数量。
- 与旧快照无正文变化；四个导航元数据事件仅是首次发现的引用 URL 不同，官方菜单与 2,794 条引用边集合一致。

机器摘要及输入/解析器哈希见[验收记录](../../validation/2026-11-16-document-inventory.json)。远端验收以本批 PR 和主分支实际 CI 为准。

## 拒收与边界

早期候选虽通过合成测试，真实全库扫描仍因循环不推进而卡住，并误拒绝未引用模板。该候选已拒收；修订后才得到上述全库结果。一次派单遗漏了执行方可见的文件/命令清单，已修正为自包含派单，未执行的检查不计通过。额外命令和越界文件尝试的拒绝记录与实际成功检查分开核对，不描述为全程无偏离。

缺页、未解析观察及业务语义不确定性仍保留。源码哈希和结构验证不等于全量业务契约正确；本批没有真实设备调用。安全诊断、运行反馈、App adapter、更多接口域、受控 RSI 和发行仍属后续工作，本阶段交付不代表整个产品完成。
