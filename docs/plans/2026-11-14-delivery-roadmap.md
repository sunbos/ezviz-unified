# EZVIZ Unified 实施路线

**目标：** 持续完成统一国内与海外官方能力的 Python SDK，并建立可验证的维护流程；App 数据扩展与受控自我改进按独立阶段推进。任何单个批次完成都不代表整个目标完成。

**产品边界：** `ezviz-unified` / `ezviz_unified` 是独立产品，要求 Python 3.12+，不提供旧utils兼容层，不以旧方法迁移率定义完成度。仓库为 `sunbos/ezviz-unified`；代码、文档、CI与包链接已核验，独立仓库已公开，旧 `ezviz-openapi-utils` 已归档只读。

**分工：** Codex 负责架构、关键验收与集成；Claude Code 经 Magpie 使用 `devin/swe-2`、effort=max，执行边界明确的整理和实现任务。后台只读任务生成候选结果，Codex 审核后写入；不关闭后台隔离规则。

## 当前状态

- 同步/异步客户端、国内/海外区域认证、惰性token管理、外部token provider、显式传输与响应解析已实现；普通SDK调用不依赖LLM。
- 已覆盖业务域：设备查询与管理、本地录像、云台/预置点/国内巡航、设备开关、图像参数、视频配置、播放地址与抓拍、告警、云存储、国内云录制2.0、RAM子账户、维护/补光、视频加密与布撤防、国内单步确权、设备诊断。各域入口、地区限制与未验证项见 README 及 `docs/research/` 对应说明；登记数量、地区分布与验证状态以[机器生成的覆盖清单](../../contracts/coverage.json)为准，不把当前计数当作永久承诺。
- 验证现状：全部已登记契约通过离线传输评测。国内与新加坡账号认证/列表已实测，新加坡需显式 `auth_base_url`；用户后续接入国内设备，基本信息、通道、状态、能力与版本查询已通过单设备只读验收。具体动作、其他型号和海外设备仍未验证；写操作按明确范围另行验收。
- 维护harness：门户catalog差异检测、逐页来源关联、直接影响定位、登记/AST符号一致性、机器覆盖摘要、契约离线评测与CI过期摘要检查已实现；新增基础维护语义评分器及一次真实模型的8项合成案例记录。补丁级eval、自动修复和发布闭环仍未完成。
- 维护审查任务包已把门户快照完整性、基线来源、变化任务和SDK合成评测串联；保留标题/导航评估、共享核心提示和全部相关源问题，始终不授予发布许可。静态SDK/附件变化和候选生成仍待接入。
- 文档来源缺项：仍有48条门户记录与3个静态参考链接未返回内容；已关联文档不等于完整端点覆盖，不承诺零缺失。
- 发行工程：wheel/sdist 构建、元数据与归档边界检查、干净环境安装验证脚本就绪；版本 `0.1.0a1` 未发布 PyPI。
- 统一存储引擎的七项API已离线封装，保留源搜索优先级、永久期限、可选字段和跨产品边界；云录制计划管理另完成五项显式写接口，保留响应层级及条件必填差异。空间/文件/权限和录制计划修改均未实测。

## 验收规则

接口数、文件数、跳过测试和模型完成声明都不能代替正确性证据。离线、真实只读、真实写操作及维护 eval 分开报告。不会为满足覆盖目标猜测官方缺项或自动操作真实设备的破坏性接口。

源码与运行依赖留在核心包；原始文档数据、模型调用和维护调度不进入 SDK wheel。每阶段有具体交付与验证记录，未完成阶段继续保留在路线中。
